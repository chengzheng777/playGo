# 008 · 像素房间入座

- 状态：active
- 关联：`specs/001-room-and-lobby.md`、`docs/PROTOCOL.md`、`docs/JOIN-SCENE.md`、`CHANGELOG.md`
- 新增接口：`GET /api/rooms/:code`
- 变更消息：`room.join` 增加可选 `seat`、`ready`

## 背景

现在扫码打开 `/j/:code` 是一张表单：输入/确认房间码，点「进入房间」，进大厅后还要再点一次「加入游戏」。
玩家在点按钮之前看不到房间、已经坐下的人和有没有空位。把这段入口换成像素风格的房间，走到椅子旁坐下就算加入，
把「加入房间」和「准备」合成一个动作。

## 用户故事

- 作为扫码进来的玩家，我想先看到这间房、已经坐下的人，再决定坐哪。
- 作为房主，我希望别人坐下就算加入，不用再催「点加入游戏」。
- 作为手机玩家，我希望能用一只手走到椅子旁坐下，不要求鼠标悬停或精确点击。

## 行为

### 入口与预览

- 扫码、房间列表「加入」、输入房间码，最终都打开 `/j/:code` 的像素房间，不立即加入房间。
- 打开场景时，房间人数、大厅列表和 `room.state` 都不因这次浏览而变化。
- 场景显示房间码、游戏、房主、可玩座位数和已坐人数。
- 已坐玩家在最多 2 秒内出现在场景中；座位被占、玩家离开、掉线都会随预览刷新。
- 本机已有该房间的 token 时，打开 `/j/:code` 直接重连回大厅，不重新入座。
- 返回按钮回到大厅首页；浏览场景不产生房间成员，不需要服务端清理。

### 座位

- 椅子数量 = 可玩座位 = `maxPlayers` 减去不参赛房主占用的 1 个；房主参赛时为 `maxPlayers`。
- 观战大屏（`spectator`）不占桌上的椅子。
- 房主不参赛时站在墙边大屏旁，不坐椅子；房主参赛时与其他玩家一样坐椅子。
- 每把空椅都可以坐；已坐玩家占椅时显示头像和名字；掉线玩家仍占椅，并标记为掉线。
- 座位以服务端分配为准；客户端点椅子只是表达偏好，不能决定最终座位。

### 移动与坐下

- 玩家可以在房间内移动，不能穿过墙、圆桌和椅子。
- 靠近空椅时出现「坐下」操作；点击后播放入座动作，然后加入房间。
- 坐下 = 加入房间 + 准备（ready），两步原子生效；成功后进入大厅，自己显示为「已加入」。
- 已坐的椅子不能坐；点已坐的椅子只显示该玩家的名字和头像。
- 手机提供触控移动方式，桌面提供键盘移动方式；所有关键操作不依赖悬停。
- 玩家和房主的名字用清晰文字标签显示，不跟随场景像素化模糊；标签跟随角色移动。
- 入座失败时保持在场景内并提示原因，玩家站在椅子旁，可以改名或换椅子重试。

### 边界与异常

| 场景                      | 期望                                                              |
| ------------------------- | ----------------------------------------------------------------- |
| 房间不存在 / 已销毁       | 显示「房间不存在或已结束」，不能坐下，可返回大厅                  |
| 游戏已开始                | 不能坐下，提示「这局已经开始了」；房间回到 `lobby` 后自动恢复可坐 |
| 房间满员                  | 没有可用空椅，提示人已坐满                                        |
| 昵称已被占用              | 不进入房间，提示改名并可打开资料编辑；改名后可继续坐              |
| 两个玩家同时坐同一把椅子  | 服务端分配不同座位，两人都能加入；不会出现两人占同一把椅子        |
| 坐下瞬间房间状态变化      | 服务端拒绝并提示，页面停留在场景，不出现「半加入」状态            |
| 网络断开 / 加入超时       | 提示失败并站起，可重试                                            |
| 未入房时切后台 / 刷新     | 不保留房间成员；重新打开可重新预览                                |
| WebGL 不可用或上下文丢失  | 出现等价的 2D 像素座位列表，仍可完成入座                          |
| 手机 320 / 360 / 390 宽度 | 场景和 HUD 不横向溢出，「坐下」按钮始终可点到                     |
| 系统开启减少动态效果      | 关闭走动摇摆、灯光闪烁等装饰动画，功能不变                        |

## 接口

### `GET /api/rooms/:code`

按房间码读取公开房态，用于入座前的预览，不改变房间状态。

```jsonc
{
  "code": "7K2M",
  "phase": "lobby", // lobby | playing | ended
  "maxPlayers": 8,
  "hostPlays": false,
  "hostSeat": 0,
  "host": { "name": "房主", "avatar": {} },
  "gameId": "draw",
  "seats": [
    { "seat": 0, "role": "screen", "name": "房主", "avatar": {}, "connected": true },
    null,
    { "seat": 2, "role": "player", "name": "小明", "avatar": {}, "connected": true }
  ]
}
```

- `seats` 长度等于 `maxPlayers`，下标即座位号；空位为 `null`。
- 只返回房间码、阶段、容量、房主座位、游戏和座位的公开昵称/头像/角色/在线状态。
- 不返回玩家 id、token、准备状态、手牌、词语、照片等内容。
- 房间不存在返回 `404`；同一来源请求过频返回 `429`。
- 该接口不受大厅「房间发现」开关影响，扫码和房间码加入仍可使用。

### `room.join`

```jsonc
{
  "v": 1,
  "type": "room.join",
  "data": {
    "code": "7K2M",
    "name": "小明",
    "role": "player",
    "avatar": { "text": "明", "color": "#3ee08f" },
    "seat": 3, // 可选：期望座位
    "ready": true // 可选：加入时同时准备
  }
}
```

- `seat` 为 0 起的整数；指定座位空闲时采用，被占用时分配最近的空闲座位，并返回实际座位。
- 没有空闲座位时返回 `ROOM_FULL`；非 `lobby` 阶段返回 `BAD_PHASE`。
- `ready` 只对 `role: "player"` 生效，加入后立即计入已准备；大屏忽略该字段。
- 重连（带 `token`）不改变已有座位和准备状态。
- 不新增 WebSocket 广播消息；入房后仍使用现有 `room.state`。

## 验收标准

- [x] 打开 `/j/:code` 只做预览，不加入房间，房间人数不变
- [x] 场景在最多 2 秒内显示已坐玩家、空位、房主和房间码
- [x] 椅子数量符合「可玩座位」规则，房主大屏位不出现空椅，观战大屏不占椅
- [x] 玩家可以移动，且不能穿过墙、圆桌和椅子
- [x] 靠近空椅出现「坐下」，完成后进入大厅并显示已加入
- [x] 坐下与准备原子生效，房主无需再等待该玩家点「加入游戏」
- [x] 已坐椅子不能坐，点它只显示玩家名片
- [x] 两人抢同一把椅子时都能入房且座位不同
- [x] 房间不存在、已开局、满员、重名时都有明确提示且不会半加入
- [x] 预览接口不泄露玩家 id、token 和游戏私密字段
- [x] 有 token 时打开 `/j/:code` 直接回大厅，不重新入座
- [x] 无 WebGL 时 2D 座位列表可完成同样的入座流程
- [x] 320 / 360 / 390 宽度下无横向溢出，「坐下」按钮可点到
- [x] 名字牌清晰可读，不跟随 320p 像素化模糊
- [x] 减少动态效果下功能不变
- [x] 房主建房、大厅、踢人、房主参赛、四种游戏流程不受影响

## 不做

- 多人实时同步走位（没坐下之前不在房间里，看不到别人走动）
- 自由旋转镜头、第一人称、自由视角
- 家具/皮肤/房间装修系统
- 大厅和对局画面的像素化（本期只改 `/j/:code` 的入座阶段）
- 观战预览、排队等位、房间搜索
- 账号、跨设备同步
