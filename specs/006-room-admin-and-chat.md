# 006 · 房间管理与对局聊天

- 状态：active
- 关联：`shared/protocol.ts`、`server/hub.ts`、`src/components/PlayerList.tsx`、`src/components/GameChat.tsx`
- 新增消息：`player.kick`
- 新增错误码：`KICKED`

## 背景

开局必须所有在线手机玩家都「加入游戏」，只要有人没准备，房主就卡在开始按钮上；房主目前也没法把捣乱或占位的人请出去。
进入对局后大厅的聊天面板消失，玩家没有公屏可以交流。

## 行为

### 房主踢人

- 仅房主可以踢人；房主不能踢自己。
- 仅 `lobby` 阶段可以踢人。游戏进行中想踢人，先「结束」回大厅。
- 房主在玩家列表里对任意非房主玩家点「移出」，确认后该玩家立即从房间移除。
- 房主可以点「移出未准备」，一次性移除所有未准备的非房主玩家（含离线玩家）。
- 被移出的玩家：本机回到首页，提示「你被房主移出房间」；重连凭证立即失效，不能凭旧 token 回到房间。
- 房间内其他玩家立刻收到更新后的玩家列表。
- 移出后若房间人数不满足开局条件，开始按钮按现有规则提示原因。

### 对局聊天

- 所有游戏（一愚惊人、UNO、拍颜色、你画我猜）进行中都有公屏聊天。
- 聊天以右侧悬浮栏呈现：默认收起，只显示一个「聊天」入口；点击展开，再点收起。
- 展开后的面板为半透明深色，带背景模糊，不整页遮挡游戏；宽度不超过屏幕宽度，手机和大屏都可用。
- 收起时若有新消息，入口显示未读数；展开后未读数清零。
- 对局聊天与大厅聊天共用同一份消息历史和 `chat.send`，频率限制不变。
- 发送者自己显示为「你」，其他消息显示昵称；新消息自动滚动到底部。
- 手机 320 / 360 / 390 宽度下，聊天入口可见、面板完整落在视口内，不产生横向滚动。

## 接口

```jsonc
// C→S，仅房主、仅 lobby
{ "v": 1, "type": "player.kick", "data": { "playerId": "p-xxxx" } }
```

- 成功：服务端移除玩家、广播 `room.state`，并向被踢玩家的所有连接发送
  `error { code: "KICKED", message: "你被房主移出房间" }` 后关闭连接。
- 非房主、目标不存在、目标是房主自己、或当前不在 `lobby`：回 `NOT_HOST` / `BAD_PHASE`，状态不变。
- 聊天仍使用 `chat.send` / `chat.message`，无协议变化。

## 验收标准

- [x] 房主在玩家列表能把任意非房主玩家移出房间
- [x] 非房主不能踢人
- [x] 被踢玩家回到首页并看到原因，旧 token 不能重连
- [x] 房主可一键移出所有未准备玩家
- [x] 游戏进行中不能踢人，先回大厅再操作
- [x] 四种游戏对局中都能打开/收起悬浮聊天栏并互发消息
- [x] 聊天收起时新消息显示未读数，展开后清零
- [x] 对局聊天与大厅聊天共用历史
- [x] 移动端 320 / 360 / 390 宽度下聊天面板不超出视口，且无横向滚动

## 不做

- 对局中踢人、封禁、黑名单
- 私聊、@提醒、图片/表情包
- 聊天记录持久化到服务端磁盘
- 拖拽改变聊天栏大小
