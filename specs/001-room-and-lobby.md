# 001 · 用户、房间与大厅

- 状态：active
- 关联：`shared/protocol.ts`、`server/rooms.ts`、`server/hub.ts`

## 背景

PC 起本地服务，手机扫码或从列表进房。用户不需要账号，但要有一致的身份（名字 + 头像）。

## 行为

### 用户

- 首次打开创建本机用户：名字 1–16 字，头像为 1–2 字符或一个 emoji + 颜色。
- 资料存 `localStorage`，之后免填；大厅用户栏可修改，房间内修改实时同步给其他人。
- 服务端对名字做重名校验、长度校验；头像文本截断到 2 个字符。

### 房间

- 大厅选游戏后创建房间，生成 4 位房间码（去除 `0 O 1 I`）与二维码。
- 加入方式：大厅房间列表点击、输入房间码、扫二维码。
- 房间列表每 3 秒轮询，另有手动刷新；显示房主、游戏、人数、阶段。
- 房间满员或不在 `lobby` 阶段时禁止加入。

### 开始条件

- 房主是大屏/主持人，**不参赛**。
- 至少 2 名已连接的手机玩家，且都已点「加入游戏」（ready）。
- 房主可以改游戏、改规则（仅 `lobby` 阶段）。

### 生命周期

- 没有在线玩家的房间立即从列表隐藏。
- 30 秒后服务端销毁；全员主动离开则立即销毁。
- 掉线玩家保留座位 90 秒，可凭 token 重连。

## 接口

`GET /api/rooms` 返回公开摘要；`room.create / join / leave`、`player.ready / update` 见协议文档。

## 验收标准

- [x] 首次打开进入创建用户页，创建后进入大厅
- [x] 房间出现在 `/api/rooms`，全员离线后从列表消失
- [x] 1 名手机玩家时不能开始；2 名且都已加入才能开始
- [x] 非房主不能选游戏、改规则、开始
- [x] 重连不新增座位，90 秒内恢复身份
- [x] 头像在加入房间后保留（不是名字首字）

## 不做

- 账号体系、跨设备同步、密码/登录
- 房主同时参赛
