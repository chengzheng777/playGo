# 009 · 大厅像素房与位置同步

- 状态：active
- 关联：`specs/008-join-room-scene.md`、`docs/PROTOCOL.md`、`docs/LOBBY-SCENE.md`、`CHANGELOG.md`
- 新增消息：`player.move`、`player.moved`
- 数据结构：`Player` 增加可选 `x` / `z` / `facing`

## 背景

入座场景是像素房间，但玩家坐下进入大厅后就只剩表单和聊天，PC 房主看不到“人坐在桌边”的画面；
手动点「加入游戏」的玩家也没有地方走动。大厅需要一个常驻的像素候场区，准备后还能站起来走动，
并且让房主和其他同桌看到彼此的位置。

## 行为

### 显示位置

- PC 大厅以候场房为主界面：场景铺满顶栏下方，游戏、玩家、设置、邀请做成场景内按钮打开居中弹窗；聊天在场景左下角悬浮；手机/桌面玩家大厅在内容顶部显示像素房，下面的面板保留。
- 手机窄屏下像素房排在玩家列表和聊天之前，不能被固定底栏完全遮住。
- 像素房展示房间码、圆桌、椅子、房主大屏和所有参赛者；观战大屏不出现。
- 准备（ready）的玩家坐在自己的椅子上；未准备的玩家站在椅子旁。
- 空椅用绿色描边标记；已被分配但暂时走开的椅子保留座位标记，不显示为空位。
- 房主只做大屏时站在墙边大屏旁；房主切到「我也玩」后坐自己的椅子。

### PC 主界面与操作

- 顶栏（房间码、头像、连接状态、离开）保留；下方只放候场房，不再常驻左侧设置/游戏栏和右侧聊天栏。
- 场景右上角按钮：`游戏`、`玩家 N`、`聊天`；房主额外有 `设置`、`邀请`。
- `游戏`/`设置`/`玩家`/`邀请` 打开房间弹窗，分别滚到游戏、房主模式、玩家列表、二维码/大屏链接；`聊天` 在 `lobby-room-stage` 左下角悬浮，聊天按钮和“收起”切换显示。
- 弹窗可以用关闭按钮或点遮罩关闭；聊天可以收起/重新打开；两者都不改变场景的主界面地位。
- 房主的开始游戏和移出未准备玩家在底部固定操作条；玩家的加入/取消准备也在底部操作条。
- 场景在宽屏下最大 2000px、16:9 居中，4K 也保证房间上下完整；聊天悬浮框在场景内，不挤占场景宽度。
- PC 页面高度锁在 100dvh，不出现整体纵向滚动条；房间弹窗和悬浮聊天在自己的容器里滚动。
- 弹窗/聊天不改变房间状态；手机宽度下自动回到原来的上下堆叠布局，不显示弹窗和悬浮聊天。

### 移动

- 玩家可以在大厅像素房里点地面、按 WASD / 方向键，或在触屏上用摇杆走动；不能穿过墙、圆桌和椅子。
- 准备后仍可以站起来走动；准备状态和座位都保留。走到自己的椅子旁停下会自动坐回去。
- 点「加入游戏」时，本机小人直接坐到自己的椅子上；点「已加入 · 取消」时起身站到椅子旁。
- 房主（大屏）也能走动，默认站在大屏旁；位置同样同步给房间内其他人。
- 移动只影响大厅里的小人，不影响游戏规则、座位归属、准备状态或开局条件。

### 同步

- 本机移动以约 10Hz 发送 `player.move`；服务端校验边界和频率后广播 `player.moved`。
- 其他客户端把收到的位置插值到小人和清晰名字牌上；房主和同桌能看到谁在桌边走动。
- 服务端把最后位置存在玩家上；刷新/重连后，`room.state` 会带回位置，不需要重新走一遍。
- 只在 `lobby` 阶段接受移动；游戏中和观战大屏不参与位置同步。
- 位置是装饰性的，服务端只做范围夹紧（约 `[-5.2, 5.2] × [-4.2, 4.2]`）和每连接约 20 次/秒节流。

### 边界与异常

| 场景                          | 期望                                                                    |
| ----------------------------- | ----------------------------------------------------------------------- |
| 没人动过 / 刚坐下             | 按座位和准备状态给默认站位，画面不空                                    |
| 准备后走开                    | 小人站起来走动，椅子仍保留；准备标签和开局条件不变                      |
| 准备后回到椅子旁              | 自动坐回椅子                                                            |
| 房主切换「我也玩 / 只做大屏」 | 小人从大屏旁走到椅子，或从椅子走回大屏旁                                |
| 重连 / 刷新                   | 恢复上次位置；没有位置时按当前座位/准备状态给默认站位                   |
| 移动消息越界                  | 服务端夹紧到房间范围，不报错、不踢人                                    |
| 走动绕圈导致朝向累积          | 客户端发送前归一化，服务端也归一化到 `[-π, π]`，不触发 `PROTOCOL_ERROR` |
| 游戏进行中                    | 忽略移动消息；回到大厅后继续使用保存的位置                              |
| 网络抖动                      | 位置事件丢失只影响画面，不阻塞准备/开始；下一次全量状态会校正           |
| 手机窄屏 / 320 宽             | 像素房在顶部、无横向溢出，固定底栏不挡主要操作                          |

## 接口

### `player.move`（C→S）

```jsonc
{ "v": 1, "type": "player.move", "data": { "x": 1.25, "z": 2.5, "facing": 0.75 } }
```

- `x` / `z` 使用房间坐标；`facing` 是朝向弧度，可选。
- 仅 `lobby` 阶段、非观战角色生效；越界由服务端夹紧。
- 每连接约 20 次/秒节流，超过的包直接忽略。

### `player.moved`（S→C）

```jsonc
{
  "v": 1,
  "type": "player.moved",
  "data": { "playerId": "p-xxxx", "x": 1.25, "z": 2.5, "facing": 0.75 }
}
```

- 只广播位置，不改变 `version`，不触发完整 `room.state`。
- `room.state` 里的 `Player` 也会带最后位置，重连时使用。

## 验收标准

- [x] PC 大厅以候场房为主界面，场景铺满顶栏下方
- [x] PC 场景按钮能打开房间/玩家居中弹窗；聊天在场景左下悬浮
- [x] 悬浮聊天打开/收起不压缩场景，收起后能重新打开
- [x] PC 大厅和悬浮聊天都不产生整体纵向滚动条
- [x] 4K 宽度下场景受控、房间上下完整可见
- [x] 房主的房主模式、游戏选择/规则、二维码/大屏链接、玩家列表、开始游戏都可达
- [x] 玩家的加入/取消准备在 PC 底部操作条可达
- [x] 手机/桌面玩家大厅能看到像素房，窄屏排在玩家列表和聊天之前且无横向溢出
- [x] 准备玩家坐椅子、未准备玩家站旁边、空椅有绿色标记
- [x] 房主大屏在墙边，切换房主参赛后坐到椅子上
- [x] 准备后可以站起来走动，准备状态和座位不变
- [x] 点「加入游戏」坐到椅子，取消准备时起身
- [x] 本机位置以约 10Hz 同步，房主/同桌能看到其他小人移动
- [x] 重连恢复上次位置；没有位置时按座位/准备状态给默认站位
- [x] 越界移动被服务端夹紧；游戏中忽略移动
- [x] 名字牌清晰可读，不跟随像素场景模糊
- [x] 大厅、踢人、房主参赛、开局和四种游戏流程不受影响

## 不做

- 物理引擎、跳跃、攀爬、家具互动
- 大厅自由旋转镜头 / 第一人称
- 位置持久化到服务重启后（只存在当前房间内存）
- 独立大屏 `/s/:code` 的像素房（本期只做房主大厅和玩家大厅）
- 游戏内走位同步
