# playGo

局域网多人 Web 游戏平台：PC 起本地服务并创建房间，手机扫码即加入。目标形态是卡片游戏与多人在线活动小游戏。

## 状态

**M0 通讯层已跑通**（2026-11-05）。回合制玩法，WebSocket 足够，暂不需要 WebRTC。

## 快速开始

```bash
pnpm install
pnpm dev
```

浏览器打开 <http://localhost:8787>，输入名字 → 创建房间 → 手机用系统相机扫二维码。

手机和电脑要在**同一个 WiFi**；Windows 首次运行时防火墙会弹窗，勾选「专用网络」。

## 已验证的能力

- 创建房间，生成 4 位房间码与二维码（自动带局域网 IP）
- 手机扫码加入、设置昵称，房主与玩家角色分离
- 房间状态全量广播、准备状态同步
- 聊天
- 断线后 90 秒内重连，座位与身份保留
- 多网卡时手动切换二维码地址（VPN / Docker / WSL 虚拟网卡会被排到后面）
- 端口被占用自动顺延；生产模式单端口部署

## 脚本

| 命令 | 说明 |
| --- | --- |
| `pnpm dev` | 开发模式，Vite 中间件 + HMR，默认 8787 |
| `pnpm build` | 构建前端到 `dist/` |
| `pnpm start` | 生产模式，需先 build；`PORT=xxxx` 可改端口 |
| `pnpm typecheck` | TypeScript 类型检查 |
| `pnpm smoke` | 对着运行中的服务跑一遍协议冒烟测试 |


## 手机连不上？

1. 确认手机连的是同一个 WiFi，不是 5G 蜂窝。
2. Windows 防火墙允许 Node 访问「专用网络」。
3. 路由器若开了「AP 隔离 / 访客网络」，设备之间互相不通，换手机热点。
4. 二维码下方可以切换网卡；虚拟网卡（VPN、Docker、WSL）通常连不通。
5. 端口 8787 被占用时会自动换成 8788…，以启动日志里的地址为准。
