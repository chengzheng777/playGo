# 加入房间 · 像素场景设计

> 状态：已实现（2026-11-15）
> 关联：`specs/008-join-room-scene.md`、`docs/PROTOCOL.md`
> 范围：只改 `/j/:code` 的入座阶段，不改大厅和对局画面。

## 1. 已确认的取舍

| 决策     | 结论                                                               |
| -------- | ------------------------------------------------------------------ |
| 场景范围 | 只做加入场景；坐下后进入现有大厅                                   |
| 坐下语义 | 坐下 = 加入房间 + 准备（`room.join` 带 `ready: true`）             |
| 椅子数量 | 按可玩座位：房主只做大屏时 7 把，房主也参赛时 8 把；观战大屏不占椅 |
| 房态预览 | 新增只读 `GET /api/rooms/:code`，客户端每 2 秒轮询，不新增 WS 消息 |

结论：three.js 只负责 `/j/:code` 的场景渲染，玩法规则和座位归属仍由服务端决定。

## 2. 体验流程

```
打开 /j/:code
  ├─ 本地有该房 token ────────────────→ 直接重连，进大厅
  └─ 无 token → 像素房间（预览，不占房间）
        ├─ 点击地面 / 摇杆 / WASD 移动
        ├─ 靠近空椅 → 出现「坐下」
        └─ 坐下 → 0.35s 动画 → room.join{seat, ready:true}
              ├─ 成功 → 现有大厅（自己已准备）
              └─ 失败 → 站起 + toast，留在场景

预览轮询：每 2s 更新 seats，最多 2s 后看到别人坐下/离开/掉线
```

状态机（客户端）：

```
loading → previewing ⇄ sitting → joining → done
                └────→ blocked（notFound / playing / full）
```

## 3. 画面

### 3.1 镜头

- 正交相机，固定机位；水平转角 45°，俯角约 32°，不做旋转和缩放。
- 近侧两面墙不渲染（dollhouse 切角），保留 `-X`、`-Z` 两面墙，避免遮挡桌子。
- 相机取景优先保证桌子和椅子完整：按画面高度取景，宽屏封顶；竖屏裁掉房间两侧多余部分，桌子始终在画面中心。

### 3.2 像素化管线

- 内部渲染分辨率固定高度 320px（宽度按屏幕比例），CSS 放大到全屏，`image-rendering: pixelated`。
- `antialias: false`、`setPixelRatio(1)`、关阴影、关色调映射；颜色输出 sRGB。
- 贴图全部程序化生成，16×16，`NearestFilter`；不用外部图片，不增加下载。
- 渲染上限 30fps；页面隐藏、场景不可见时停渲染。
- 灯光用一盏半球光 + 一盏方向光做明暗，蜡烛用自发光材质；角色和家具的“影子”用半透明贴地圆片伪造。

### 3.3 空间构成

- 房间约 11×9 个世界单位，木地板 + 木梁 + 灰泥墙；后墙有窗（夜空像素），左墙挂大屏。
- 中间橡木大圆桌：直径约 4.2，桌面木板纹理，4 条桌腿，桌上放一盏小灯/杯子做点缀。
- 椅子按座位数均匀环绕，半径约 2.95；木椅 = 坐面 + 靠背 + 四腿，朝向桌心。
- 空椅：品牌绿像素描边 + 轻微呼吸光；靠近时高亮加强。
- 房主只做大屏时，大屏旁显示房主小人 + 「大屏」标签，不坐椅子。
- 蜡烛、地毯、墙角绿植做暖色点缀，控制在低面数，不喧宾夺主。

### 3.4 角色

- 方块小人：头 + 身体 + 两条手臂 + 两条腿，总高约 1.45。
- 衣服颜色取头像 `avatar.color`；头发布色按名字哈希，保证同一玩家每次一致。
- 头顶名字牌：覆盖在 3D 画布上的清晰 2D 标签（按 DPR 缩放），显示头像字 + 昵称（最多 8 字，超出省略）和「大屏」/「你」/「掉线」状态；像素画布保持低分辨率，文字不跟着糊。
- 走路两帧摆腿，坐下时腿部前折、身体下沉并转向桌心；静止时做 3fps 的阶梯式轻微起伏。
- 自己的小人与已坐玩家同款，避免“主角光环”破坏像素统一感。

### 3.5 色板

| 用途      | 色值                          |
| --------- | ----------------------------- |
| 地板      | `#8a5f3c` / `#a4714a` 交替    |
| 墙面      | `#d7c6a8` / `#c2ab88`         |
| 橡木桌    | `#c9a063`，暗部 `#7b5735`     |
| 椅子      | `#b98b52`，暗部 `#8a6238`     |
| 蜡烛暖光  | `#ffd98a`                     |
| 空位/交互 | `#3ee08f`（沿用品牌绿）       |
| 背景/阴影 | `#0d0f14` / `rgba(0,0,0,.35)` |

## 4. 交互

### 4.1 输入

- 触屏：点地面走；左侧固定虚拟摇杆持续移动；点空椅自动走到椅子旁。
- 桌面：WASD / 方向键移动，点击地面移动，`E` / 空格 / 回车坐下。
- 相机不跟随旋转，玩家始终在画面内；只做很小的位置跟随（可选，不超过 1 个世界单位）。

### 4.2 碰撞

- 房间边界用矩形限制；圆桌用半径 2.05 的圆；椅子用半径 0.3 的圆。
- 角色半径 0.22，碰撞后沿切线滑动，不卡死；站立点在椅子外侧约 0.8。
- 所有碰撞在 2D 平面计算，忽略高度，逻辑可单测。

### 4.3 入座

1. 靠近空椅（距离 < 0.65）→ 高亮 + 底部「坐下」按钮。
2. 点「坐下」→ 锁定输入，播放 0.35s 从站立点到座位的位移动画。
3. 动画结束 → `room.join`，带 `seat` 和 `ready: true`。
4. 收到 `room.state` → 现有大厅接管页面；若服务端换了座位，不额外提示。
5. 失败 → 0.25s 站起，保留在当前椅子旁，toast 显示原因。

抢座：因为座位由服务端分配，两个客户端同时坐同一把椅子时，第二个会被分到别的空位。
因为坐下后马上离开场景，视觉上不会出现“两个人坐一把椅子”。

### 4.4 拒绝与异常

| 情况           | 客户端表现                                                 |
| -------------- | ---------------------------------------------------------- |
| 404 / 房间销毁 | 门口提示 + 返回大厅，停止轮询                              |
| 已开局         | 不显示空椅高亮，提示「这局已经开始了」，继续轮询等待回大厅 |
| 满员           | 所有椅子显示已坐/无空位，提示人满                          |
| 重名           | 打开资料编辑弹窗，改名后继续                               |
| 加入超时/断网  | 12s 超时，站起 + 重试按钮                                  |
| WebGL 失败     | 立刻切 `lite` 座位列表，不阻塞入座                         |

## 5. 数据流

### 5.1 预览

- `GET /api/rooms/:code`，每 2 秒一次；`visibilitychange` 隐藏时暂停，回来立即拉一次。
- 404 后停止轮询；429 后退避（4s、8s，最多 30s）。
- 预览数据只用于画面，不写入 `store` 的 `room`，避免误以为已入房。
- 房间码来自路由，客户端只接受服务端返回的公开字段。

### 5.2 入座

- 客户端只发 `room.join { code, name, role: "player", avatar, seat, ready: true }`。
- 服务端校验房间、阶段、容量、重名、座位；返回实际 `you.seat`。
- 成功后的全量状态复用现有 `room.state`；`store` 进入 `lobby`，场景卸载。
- 客户端不根据点击的椅子自行决定座位，也不在本地写任何房间成员状态。

### 5.3 座位分配

- 座位只在参赛者（`player` / 未参赛房主 `screen`）之间分配，`spectator` 不占座位号。
- 指定座位空闲 → 采用；否则从该座位开始顺时针找最近空位；没有空位 → `ROOM_FULL`。
- 座位号 0 起；预览 `seats` 数组下标就是座位号。
- 断线玩家的座位保留 90 秒，预览里仍显示为占用和掉线。

## 6. 代码结构

```
src/views/JoinRoomView.tsx        # 页面状态：预览、错误、HUD、入座动作
src/scene/world.ts                # 建场景、方块小人、移动、碰撞、清晰名字标签
src/scene/JoinRoomScene.tsx       # three.js 挂载/卸载，React 与场景的边界（懒加载）
src/scene/layout.ts               # 纯函数：椅子布局、站立点、碰撞、相机取景
src/scene/textures.ts             # 16×16 程序化贴图
src/lib/room-preview.ts           # 预览请求、轮询、退避
src/components/JoinRoomHud.tsx    # 房间码、人数、资料、返回
src/components/SeatMapLite.tsx    # 2D 兜底座位列表
```

- `three` 只在 `JoinRoomScene.tsx` 的动态 import 里出现，首页不加载。
- 布局/碰撞/相机取景是纯函数，放 `src/scene/layout.ts`，用 Vitest 覆盖。
- 场景对象全部在 `dispose()` 里释放 geometry / material / texture / renderer。

服务端：

```
server/rooms.ts                   # preview(code)、join(..., seat, ready)、座位分配
server/index.ts                   # GET /api/rooms/:code + 限流
shared/protocol.ts                # RoomPreview / SeatView / room.join 字段
```

## 7. 性能与降级

- 预算：静态场景 < 200 draw call、< 60k 三角形；低端手机 30fps；首帧 < 300ms（不含下载）。
- 所有椅子/桌子/墙体的静态几何共享材质；同一个 mesh 不重复创建纹理。
- 场景 chunk 懒加载，目标 gzip < 200KB；`pnpm build` 确认主包没有变大。
- 兜底顺序：WebGL2 → WebGL1 → `lite` 座位列表；`webglcontextlost` 时也切 `lite`。
- `?renderer=lite` 强制 2D，供 e2e 和弱设备使用。
- `prefers-reduced-motion: reduce`：关闭摇摆、灯光闪烁和相机跟随，保留 0.15s 淡入。

## 8. 测试

- 单元：`tests/join-scene.test.ts` 覆盖椅子数量/角度、空位判定、碰撞滑动、相机取景、座位→椅子映射。
- 服务端：`tests/rooms.test.ts` 覆盖指定座位、被占回退、满员、观战不占座、`ready` 原子生效、重连不换座。
- 冒烟：`pnpm smoke` 覆盖预览字段/404/不泄露 id 与 token、并发坐同一椅、预览随入房更新。
- E2E：`pnpm e2e` 用 `?renderer=lite` 走「打开 → 坐下 → 大厅已准备」，另在独立浏览器上下文测 3D 画布、已坐玩家名片、重名拒绝、token 重连和 390 / 360 / 320 宽度。
- 手测：像素观感、2.5D 遮挡、触控手感、开局中 / 满员提示、真实手机。

## 9. 实施顺序

1. 规格与协议：spec 008、`shared/protocol.ts`、`docs/PROTOCOL.md`。
2. 服务端：预览接口、`room.join` 的 `seat`/`ready`、座位分配修正、单元测试与 smoke。
3. 客户端流程（无 3D）：路由、预览轮询、`lite` 座位列表、入座成功进大厅、更新 e2e。
4. three.js 场景：静态房间/桌子/椅子/相机/像素管线。
5. 角色、移动、碰撞、坐下动画、HUD 与异常状态。
6. 降级、减少动态效果、移动端细节、截图、`pnpm verify`。

第 3 步结束时功能已经可验收；第 4–5 步只替换视觉层，便于回滚和排错。

## 10. 风险

| 风险                        | 处理                                                        |
| --------------------------- | ----------------------------------------------------------- |
| 低端手机 WebGL 掉帧         | 320p 内部渲染、30fps、静态几何共享、上下文丢失切 lite       |
| three.js 包体影响首页       | 动态 import；构建后检查主 chunk 大小                        |
| 竖屏取景裁掉椅子            | 按房间宽度取景，桌椅整体在安全区内；e2e 截图检查            |
| 2 秒轮询导致座位信息滞后    | 入座以服务端为准；抢座回退；HUD 显示的是最近一次预览        |
| 场景与大堂风格割裂          | 统一品牌绿、深色 HUD、方形描边；坐下后淡入现有大厅          |
| 昵称/座位并发               | 服务端校验 + 错误提示；客户端不本地写成员状态               |
| 旧 e2e 依赖 `/j/:code` 表单 | 同步更新 e2e helper；保留 `?renderer=lite` 作为稳定测试入口 |

## 11. 实现结果（2026-11-15）

- 依赖：`three@0.187.0` + `@types/three`；场景仍只在 `/j/:code` 动态加载。
- 产物体积：共享 3D `world` chunk 547 KB / **139.6 KB gzip**（入座和大厅共用、懒加载），主包 320 KB / 98.6 KB gzip，首页不加载 three。
- 实际实现：320p 内部渲染、正交 45°/32° 固定机位、7/8 把按座位数生成的椅子、桌上蜡烛灯、墙边大屏、窗、书架、绿植、方块小人、清晰名字标签、空位绿色高亮、点地/摇杆/WASD 移动、碰撞、0.35s 入座动画。
- 降级：无 WebGL、上下文丢失或 `?renderer=lite` 时使用同一份预览数据的 2D 座位图。
- 验证：`tests/rooms.test.ts`（8 项）、`tests/join-scene.test.ts`（6 项）、`pnpm smoke`（93 项）、`pnpm e2e`（112 项，含 3D 画布、入座、名片、重名、token 重连、390/360/320 宽度）。
- 未覆盖：真实低端手机帧率、真机触控手感、开局中/满员的完整视觉状态，留上线前手测。
