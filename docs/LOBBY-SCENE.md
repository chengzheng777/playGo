# 大厅 · 候场像素房设计

> 状态：已实现（2026-11-15）
> 关联：`specs/009-lobby-pixel-room.md`、`docs/PROTOCOL.md`、`docs/JOIN-SCENE.md`
> 范围：`/r/:code` 和 `/j/:code` 进房后的大厅；独立大屏 `/s/:code` 不改。

## 1. 和入座场景共用同一套 3D 房间

大厅候场房**复用入座场景的 three.js 体素房间**，只增加一个 `lobby` 模式：

- 同一张橡木圆桌、同一批椅子、同一套像素贴图和 2.5D 正交相机。
- 场景以 240p 内部渲染，CSS 最近邻放大；大厅卡片比手机入座页宽，所以比入座场景略低一档分辨率，保持块状像素。
- 名字牌继续用独立的 DPR 覆盖层：场景是像素的，只有名字清晰。PC 大场景按高度把名字层放大（最多 2×），避免大画面里名字太小。
- `world` chunk 与入座场景共享，大厅和入座都懒加载同一份 3D 代码；主包不增加 three.js。

## 2. 布局

- PC 大厅：候场房铺满顶栏下方的主区域，是页面主体；宽屏最大 2000px、16:9 居中，房间上下不被裁掉。
- 场景右上角的 `游戏`、`玩家 N`、`设置`、`邀请` 按钮打开居中弹窗；`聊天` 在场景左下角悬浮，按钮和“收起”切换显示。
- 弹窗/聊天框只覆盖在场景上，不挤占房间；聊天框默认打开，收起后按钮可重新打开。
- PC 页面高度锁在 100dvh，不出现整体纵向滚动条；房间弹窗和悬浮聊天在自己的容器里滚动。
- 手机/桌面玩家大厅：候场房在内容最顶部；随后是当前游戏、玩家列表、聊天；底部固定操作条。
## 3. 谁坐哪儿

- 准备（ready）的玩家坐在自己的椅子上；未准备的玩家站在椅子旁。
- 房主只做大屏时站在墙边大屏旁；房主切到「我也玩」后坐自己的椅子。
- 空椅用绿色描边；已分配但暂时走开的椅子保留座位标记，不显示为空位。
- 本地玩家用独立的站立/坐姿两个小人；准备且靠近自己椅子时显示坐姿，其余时候显示站姿。
- 本地房主（大屏）站在电视旁，也可以在房间里走动。

## 4. 状态与移动

```
room.state
  players[]: id, seat, ready, x?, z?, facing?
  hostId / hostPlays
        │
        ├─ 本地玩家：world 维护位置，10Hz 发 player.move
        └─ 其他玩家：lobbyMotion 订阅 player.moved，更新 3D 小人
```

- 本地初始位置：`you.x/z` 优先；否则准备玩家坐自己的椅子，未准备站在椅子旁，房主大屏站在电视旁。
- 点「加入游戏」：`you.ready` 变 true → 本地切到坐姿并发一次位置；点「取消」时起身站到椅子旁。
- 准备后走动：离开椅子即站起；准备状态、座位、开局条件都不变。
- 走到自己椅子旁停下且仍准备：自动坐回去。
- 碰撞复用 `src/scene/layout.ts` 的 `resolveMovement`：墙、圆桌、椅子。
- 位置只在 `lobby` 阶段发送；游戏开始后大厅卸载，回来时用服务端保存的位置。

## 5. 同步

- 客户端每约 90ms 发一次 `player.move {x, z, facing}`；停止/坐下时补发一次。发送前夹紧位置、把朝向归一化到 `[-π, π]`，服务端也会再归一化一次。
- 服务端夹紧到 `[-5.2, 5.2] × [-4.2, 4.2]`，每连接 50ms 节流，广播 `player.moved`。
- `player.moved` 不写 AppState，避免整个大厅 10Hz 重渲染；`src/lib/lobby-motion.ts` 做独立订阅，
  3D 场景只把收到的位置插值到其他人小人。
- 重连/刷新时 `room.state` 里的 `Player.x/z/facing` 是最后位置。
- 观战大屏不参与；游戏内忽略。

## 6. 代码

```
src/views/LobbyView.tsx             # PC 主界面/场景按钮/抽屉，手机原布局
src/components/LobbyPixelRoom.tsx  # 卡片、预览拼装、懒加载、摇杆、失败兜底
src/scene/LobbyRoomScene.tsx       # canvas/名字层、world 生命周期、位置订阅
src/scene/world.ts                 # 入座 + 大厅两种模式；240p 渲染、坐/站、位置
src/scene/layout.ts                # 椅子布局、坐着判定、碰撞
src/lib/lobby-motion.ts            # 高频位置流，不触发 AppState
server/hub.ts                      # player.move → 校验/夹紧/节流 → player.moved
shared/protocol.ts                 # Player x/z/facing、player.move/moved
```

## 7. 性能与降级

- 3D canvas；大厅内部 240p，入座 320p；30fps；页面隐藏时暂停。名字层按 DPR 绘制，PC 大厅额外按场景高度放大。
- 后台标签页的 rAF 会暂停，所以 resize/首帧会立即渲染一帧，避免截图或切换标签时黑块。
- `world` chunk 约 547 KB / 139.6 KB gzip，入座和大厅共享并懒加载；主包约 320 KB / 98.6 KB gzip。
- 没有 WebGL 时卡片显示“暂时画不了像素房”，大厅的准备/开局按钮不受影响。

## 8. 验证

- `tests/lobby-room.test.ts`：房主大屏位不生成椅子、坐着距离判定。
- `pnpm smoke`（93 项）：`player.move` 广播、边界夹紧、朝向归一化、位置进入全量状态、重连保留位置。
- `pnpm e2e`（108 项）：PC 以候场房为主界面，游戏/玩家/设置/邀请打开居中弹窗；聊天悬浮在场景左下；4K 宽度受控、房间上下完整；PC 无整体纵向滚动条；手机大厅在玩家列表上方；无横向溢出。
- `pnpm test`（60 项）：大厅/入座场景的纯逻辑。
- 手测：触屏摇杆、准备/取消的起身坐下、房主切换参赛、真实手机手感。

## 9. 不做

- 物理、跳跃、家具互动、自由旋转镜头。
- 独立大屏的候场像素房。
- 游戏内走位同步。
- 房间销毁后的位置持久化。
